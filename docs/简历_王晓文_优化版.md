## 项目经历

### 云仓仓储管理系统（个人独立开发）

**技术栈：** Spring Boot 3.2 + Java 21 + MyBatis Plus + MySQL + Redis + Vue 3 + Docker Compose
**部署环境：** 阿里云 ECS

**项目简介：**
面向中小企业的 WMS 仓储 SaaS 系统，包含用户权限管理、货出入库管理、库存预警及数据可视化看板。项目采用前后端分离架构，并接入 AI 智能助手实现自然语言查询库存。

**核心职责：**

1. **后端业务开发：** 使用 Spring Boot + MyBatis Plus 独立完成产品管理、出入库订单、库存预警、数据看板四大模块，统一封装响应类和全局异常处理

2. **库存并发安全：** 出库审核采用数据库行级锁（SELECT FOR UPDATE）防止超卖，商品实体用 version 字段做乐观锁，两个锁配合保障并发安全

3. **订单号生成：** 订单号格式为"IN/OUT + 日期 + 4位序号"，使用 Redisson 分布式锁保证高并发下单时序号不重复

4. **缓存优化：** 用户权限缓存到 Redis（key 格式：`user:perm:{userId}`）减少数据库查询；仪表盘数据用 @Cacheable 缓存，库存变更时用 @CacheEvict 主动失效

5. **AI 智能助手：** 基于 FastAPI + LangGraph 搭建 AI Gateway，用户可用自然语言查询库存和出入库数据，通过 SSE 流式返回 LLM 回答

6. **部署运维：** 使用 Docker Compose 编排 MySQL、Redis、后端、前端四个服务容器化部署，在阿里云 ECS 完成上线，配置安全组和防火墙

## 面试问答要点

### 1. 你在项目中学到了什么？
> 我独立完成了从开发到部署的全流程。最有收获的是库存并发问题：出库审核用数据库行级锁防超卖，订单号生成用 Redisson 分布式锁，这两个点让我理解了并发编程在业务中的实际应用。

### 2. 遇到过什么困难，怎么解决的？
> AI 助手部署时，LLM 返回的格式不标准，导致 JSON 解析报错。我查看容器日志定位问题，在代码里加了容错解析和兜底方案——LLM 返回无效时根据关键词自动选工具，问题解决了。

### 3. 你的项目有什么亮点？
> 主要有三点：一是库存并发安全，行级锁+乐观锁双重保障；二是缓存优化，权限和统计数据缓存到 Redis，减少数据库压力；三是独立完成部署上线，从代码到阿里云全链路打通。

### 4. 行级锁和乐观锁有什么区别？你们怎么用？
> 悲观锁（行级锁）是查询时加锁，别人不能改，适合冲突多的场景，比如出库审核；乐观锁是更新时比对版本号，冲突就报错，适合冲突少的场景。我们出库用悲观锁，普通库存调整用乐观锁。

### 5. Redis 在项目里用了哪些场景？
> 三个场景：用户权限缓存（减少每次请求查 DB）、Token 黑名单（退出登录时写入，24小时过期）、仪表盘数据缓存（@Cacheable，库存变更时 @CacheEvict 失效）。

### 6. 你了解微服务吗？
