### 二、专业技能逐条问答（每条练到能脱口而出）

#### Q1: Java 基础
**面试官可能问：** HashMap 底层结构？ConcurrentHashMap 怎么保证线程安全？

**你的回答：**
> HashMap 底层是数组+链表+红黑树，JDK 8 以后链表长度超过 8 会转成红黑树。
> ConcurrentHashMap 在 JDK 8 用 CAS + synchronized 保证线程安全，比 Hashtable 和 ConcurrentHashMap 1.7 的版本锁粒度更细。

---

#### Q2: Spring Boot
**面试官可能问：** @Transactional 失效场景有哪些？

**你的回答：**
> 四个常见失效场景：
> 1. 方法不是 public；
> 2. 同类方法自调用，A 调 B，B 的注解不生效；
> 3. 异常被 catch 吃掉了；
> 4. 异常类型不匹配，默认只回滚 RuntimeException。
> 我们项目用 public + rollbackFor=Exception.class + catch 里重新抛出解决。

---

#### Q3: MyBatis Plus
**面试官可能问：** LambdaQueryWrapper 和 QueryWrapper 区别？

**你的回答：**
> LambdaQueryWrapper 用 Java 8 方法引用，比如 `Product::getProductName`，编译期就能检查字段名，拼写错误不会等到运行时才报错。QueryWrapper 是字符串方式，容易拼错。

---

#### Q4: MySQL
**面试官可能问：** 索引失效的场景有哪些？

**你的回答：**
> 五个常见失效场景：
> 1. 对索引列做函数运算；
> 2. 模糊查询前面用 %；
> 3. 隐式类型转换，比如字符串字段传了数字；
> 4. OR 条件中有一列没索引；
> 5. 联合索引不满足最左前缀原则。

**面试官可能问：** 你们项目索引怎么设计的？

**你的回答：**
> 产品表 product_code、product_name 单独建索引，支持搜索；
> 出入库单表 order_no、status、create_time 建联合索引，支持分页查询；
> 审核操作用 SELECT FOR UPDATE 加行锁，靠索引锁最小范围。

---

#### Q5: Redis
**面试官可能问：** 缓存穿透/击穿/雪崩分别是什么？怎么解决？

**你的回答：**
> - **穿透：** 查不存在的数据，每次都打到 DB。解决：缓存空值，设置短过期时间。
> - **击穿：** 热点 key 过期，大量请求同时打 DB。解决：用分布式锁，只有一个线程查 DB，其他等待。
> - **雪崩：** 大量 key 同时过期。解决：过期时间加随机偏移量。
> 我们项目权限缓存没遇到穿透问题，但理解这个概念，知道怎么防御。

**面试官可能问：** Redis 在项目里用了哪些场景？

**你的回答：**
> 三个：
> 1. 用户权限缓存，key 格式 `user:perm:{userId}`，减少每次请求查 DB；
> 2. Token 黑名单，退出登录时写入，24 小时过期，JWT 注销用；
> 3. 仪表盘统计数据用 @Cacheable 缓存 1 小时，库存变更时 @CacheEvict 失效。

---

#### Q6: 并发
**面试官可能问：** 线程池参数怎么配置？核心线程数设多少？

**你的回答：**
> 线程池七个参数：核心线程数、最大线程数、存活时间、时间单位、工作队列、线程工厂、拒绝策略。
> CPU 密集型任务核心线程数设 CPU 核数+1，IO 密集型设 2 倍核数。
> 我们项目用 Spring Boot 默认线程池处理请求，没有自己配置线程池。

## Day 2（明天）：项目深度追问

### 一、核心职责逐条问答（每条练到能展开说 1-2 分钟）

#### 职责1：库存并发安全（⭐⭐⭐ 最高频）

**Q: 你们怎么解决超卖问题的？**
> 出库审核时用 SELECT FOR UPDATE 行级锁，先锁定商品记录，再扣减库存，保证并发时只有一条线程能修改。
> 同时商品实体有 version 乐观锁字段，更新时比对版本号，如果冲突就抛异常。
> 整个操作在 @Transactional 事务里，数据要么全部成功，要么全部回滚。

**Q: 行级锁和乐观锁有什么区别？为什么两个都用？**
> 行级锁是悲观锁，查询时就锁住，适合写多、冲突多的场景，比如出库审核。
> 乐观锁是更新时比对版本号，冲突就报错，适合读多写少。
> 两个配合用：行级锁保证出库时数据不被别人改，乐观锁保证库存更新本身不覆盖别人的修改。

**Q: @Transactional 失效场景遇到过吗？**
> 我们项目用 public 方法 + rollbackFor=Exception.class，两种都规避了。
> 同类方法自调用我们用 Service 注入自身的方式解决。

---

#### 职责2：订单号生成（⭐⭐）

**Q: 订单号怎么生成的？**
> 格式是 IN/OUT + yyyyMMdd + 4位序号，比如 IN202608020001。
> 用 Redisson 分布式锁 order-no-lock 保证并发下单时序号不重复。
> 先查当天最大序号，加 1 后拼接。

**Q: 为什么用 Redisson 不用 RedisTemplate？**
> Redisson 有看门狗机制，自动续期，防止业务没执行完锁就释放了。
> RedisTemplate 没有这个功能，需要自己实现。

---

#### 职责3：缓存优化（⭐⭐）

**Q: 缓存和数据库一致性怎么保证的？**
> 数据库写操作之前先删缓存，下次查询时再加载。
> 我们项目用 @CacheEvict 注解，库存变更时自动失效缓存。
> 理论上短暂不一致，但用户能接受。

**Q: 如果缓存一直失效怎么办？**
> 我们用的是 @Cacheable 缓存 1 小时，正常情况下库存不会每分钟都变更，缓存命中率较高。
> 如果担心，可以加缓存重建机制，失效后自动重新加载。

---

#### 职责4：AI 智能助手（⭐⭐ 差异化亮点）

**Q: AI 助手是怎么实现的？**
> 用 Python FastAPI 搭建 AI Gateway，接入 LangGraph Agent 工作流。
> 用户提问后，LLM 分析意图，选择对应的 WMS 工具（比如查询库存、查趋势），调用后端 API 获取数据，然后生成回答。
> 通过 SSE 流式返回，前端实时展示。

**Q: 遇到过什么问题？**
> 部署时 LLM 返回格式不标准，JSON 解析报错。
> 我加了容错解析，用正则提取 JSON 块，LLM 返回无效时用兜底方案自动选工具。

---

#### 职责5：部署运维（⭐ 应届生加分项）

**Q: Docker Compose 编排了哪些服务？**
> 四个服务：MySQL、Redis、后端 Spring Boot、前端 Nginx。
> MySQL 用数据卷持久化，Redis 开启 AOF 持久化。
> 后端依赖 MySQL 和 Redis 健康检查后启动，前端反向代理 /api 到后端。

**Q: 阿里云部署踩过什么坑？**
> 前端页面访问不了，原因是阿里云安全组没有开放 80 端口，添加入方向规则就好了。
> AI Gateway JSON 解析报错，加了容错代码。
