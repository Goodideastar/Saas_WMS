## 项目经历

### WMS 仓储管理系统（个人独立开发）

**技术栈：** Spring Boot 3.2 + Java 21 + MyBatis Plus + MySQL 8.0 + Redis + Vue 3 + Docker Compose
**部署环境：** 阿里云 ECS

**项目简介：**
一个完整的仓储管理 SaaS 系统，包含产品管理、出入库订单、库存预警、数据看板和 AI 智能助手功能，已部署至阿里云生产环境。

**我负责的内容：**

**1. 后端核心业务开发**
- 使用 Spring Boot + MyBatis Plus 开发产品管理、出入库订单、库存预警、数据看板四大模块
- 使用 LambdaQueryWrapper 实现动态条件查询，使用分页插件处理大数据量查询
- 统一封装 Result 响应类和全局异常处理（BusinessException + GlobalExceptionHandler）

**2. 库存并发安全设计**
- 出库审核时通过 `SELECT ... FOR UPDATE` 行级锁锁定商品记录，防止并发超卖
- 商品实体增加 version 字段实现乐观锁，更新时校验版本号，冲突则抛出异常
- 入库审核在 `@Transactional` 事务中执行，保证多步操作原子性

**3. 订单号生成方案**
- 订单号格式：`IN/OUT + yyyyMMdd + 4位序号`
- 使用 Redisson 分布式锁（order-no-lock）保证并发下单时序号不重复

**4. 缓存优化**
- 用户登录权限缓存到 Redis（key 格式：`user:perm:{userId}`），减少每次请求的数据库查询
- 仪表盘统计数据使用 `@Cacheable` 缓存 1 小时，库存变动时使用 `@CacheEvict` 主动失效
- 理解缓存穿透（缓存空值）、击穿（分布式锁）、雪崩（过期时间加随机偏移）的解决方案

**5. AI 智能助手接入**
- 基于 FastAPI + LangGraph 搭建 AI Gateway，用户可以用自然语言查询库存/趋势/预警数据
- 通过 SSE 流式返回 LLM 回答，前端实时展示
- 遇到 LLM 返回格式不标准导致 JSON 解析报错的问题，通过增加容错解析和兜底方案解决

**6. 部署与运维**
- 使用 Docker Compose 一键部署 MySQL + Redis + 后端 + 前端，配置数据卷持久化
- 在阿里云 ECS 上完成部署，配置安全组开放 80/443/8080 端口，配置 UFW 防火墙
- 通过 `docker logs` 和 `docker exec` 进行日常运维和故障排查
